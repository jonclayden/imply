This file provides guidance for AI agents when working with code in this repository.

## Project Overview

`imply` (a portmanteau of "image" and "apply") provides data structures for *generalised images* — two- or three-dimensional rasters that may hold a vector or time series at each location rather than a single intensity — together with infrastructure for memory-efficiently applying functions to them. The primary use case is medical imaging.

The package deliberately sits **below** the existing R imaging stack: it has no dependency on any file format, and its geometry is a plain 4x4 affine. Reading, writing and interoperating with other image classes (RNifti, tractor.base, and so on) is out of scope and left to packages that sit above this one.

**Repository:** `jonclayden/imply` (BSD-3-Clause)

Dependencies are kept tight: `Rcpp`, `S7`, `methods` in Imports; `RcppArray` additionally in LinkingTo; `tinytest` in Suggests.

## Building and testing

```bash
# After changing any [[Rcpp::export]] signature, or any roxygen comment
Rscript -e 'Rcpp::compileAttributes("."); roxygen2::roxygenise(".")'

R CMD INSTALL --preclean .

Rscript -e 'library(imply); print(summary(tinytest::run_test_dir("inst/tinytest")))'

# Full check, from a clean directory outside the package
R CMD build /path/to/imply
R CMD check --no-manual imply_0.1.0.tar.gz
```

`configure` is generated by `autoconf` from `configure.ac` and is checked in. Regenerate it with a bare `autoconf` after editing `configure.ac` or the macros in `tools/m4/`.

A clean check is **1 NOTE** (CRAN incoming feasibility: new submission, and GitHub URLs that 404 until the repository is published). Anything else is a regression.

### Things that will waste your time

- **`src/Makevars` is generated** by `configure` from `src/Makevars.in`. Editing it does nothing — `R CMD INSTALL` reruns `configure` and overwrites it. It is gitignored and excluded from the build.
- **`R CMD config CXX14` may report `-std=gnu++17`** on some R builds, so setting `CXX_STD = CXX14` proves nothing about C++14 compatibility. Test a lower standard with an explicit `clang++ -std=gnu++14 -Werror=c++17-extensions -fsyntax-only` invocation.
- **The local shell is fish.** Backslashes inside `Rscript -e '...'` get mangled (`\\b` becomes a backspace escape, not a regex word boundary). Write throwaway scripts to a file and run `Rscript file.R` instead. This has caused at least three phantom "bugs" that were only ever in the test harness.

## Architecture

Three storage representations, **one** apply engine:

| | class | storage |
|---|---|---|
| dense | `denseImage` | an ordinary R array, any of the four storage modes |
| sparse | `sparseImage` | bitset mask over spatial locations + values packed voxel-major |
| narrow | `packedImage` | a raw vector reinterpreted as float32/int16/…, with slope and intercept |

They are unified in C++ by a shared accessor interface (`DenseAccessor`, `SparseAccessor`, `NarrowAccessor`), all with an integer subscript returning a value. `gather()` in `Blocks.h` is where a narrow type is widened and an absent sparse location becomes a zero, so **no kernel needs to know which representation it is reading**. Adding a fourth representation means adding an accessor, not touching any kernel.

Key pieces:

- **`Raster<D>`** (`inst/include/imply/Raster.h`) — an index space with *general strides*, split at a runtime `spatial` index into leading spatial dimensions and trailing value dimensions. `DynamicRaster` and `FixedRaster<D>` come from one template. Note that the apply and reduce engines do **not** currently use it: they compute strides inline and walk with `OffsetWalker`. `Raster` is reachable only from the unexported probe functions in `src/raster.cpp` and from the public header API.
- **`OffsetWalker`** (`Blocks.h`) — odometer traversal of an arbitrary subset of dimensions, yielding memory offsets incrementally with no allocation. This is what lets a sub-array be gathered without permuting the whole image, which is where the 2x memory saving over `base::apply` comes from.
- **`ImageSpace`** (`Space.h`) — voxel-to-world geometry. Header-only, no file-format dependency.
- **`parallelFor`** (`Parallel.h`) — libdispatch, OpenMP or serial, dividing work into a fixed number of *chunks* so a requested thread count is meaningful on both backends.
- **Sinks** (`Sink.h`) — results are written through a preallocated typed vector where every call returns the same shape, falling back to a list otherwise. A file-backed sink would slot in here.

The public C++ API is header-only under `inst/include/`; downstream packages need only `LinkingTo: imply`.

## Conventions

- **C++ types** (classes, structs, enums, member typedefs) are UpperCamelCase. **Namespaces, functions, methods, variables and enum values** are lowerCamelCase.
- **R functions and variables** are lowerCamelCase throughout.
- **C++17**, but the only C++17 feature used is `if constexpr` (12 occurrences). Generic lambdas are the one C++14 feature, and they are load-bearing — they are how `dispatchType`/`dispatchDims`/`dispatchNarrowType` turn a runtime type into a compile-time one exactly once, at the R boundary.
- Dispatch happens **once**, at the boundary; kernels are fully typed and free of per-element branching or virtual calls. This is a deliberate departure from RNifti's `NiftiImageData`, whose proxy iterator costs an indirect call per element.
- Documentation is roxygen2 (8.0.0). `NAMESPACE` and `man/` are generated — do not edit them.

## Invariants that must not be broken

**`imapply()` gives bit-identical results to `base::apply()`.** Around 1,800 assertions check this across storage modes, dimensionalities, margins, ragged and `NULL` and named results, and both `simplify` settings. It is the package's central promise.

Consequences that are easy to get wrong:

- **Only provably exact reductions are auto-routed** to `imreduce()`: `min`, `max`, `range`, `which.min`, `which.max`, on double data. `sum` and `mean` are *not*, because R accumulates in long double and answers differ in the last place; `var` is not, because `var()` of a matrix is a covariance matrix rather than a scalar; `any`/`all` are not, because base warns when coercing double to logical and routing would swallow the warning.
- **The zero-extent check must precede routing.** `base::apply()` calls the function once on a dummy sub-array to establish the type of an empty result, and the compiled kernels have nothing to say about that.

**Nothing inside `parallelFor` may touch the R API**, allocate R objects, or draw from R's RNG. Allocate results before the parallel region and write through raw pointers. This is why `imreduce` checks for interrupts *between* slabs rather than inside the kernel.

**Use `Rcpp::Rcpp_fast_eval`, never `Rf_eval`, for callbacks into R.** R may jump out of the applied function — an error, an interrupt, a `return()` from an enclosing frame, a restart being invoked — and a bare `Rf_eval` would longjmp past every C++ frame, leaking the sinks and walkers. `R_UnwindProtect` turns the jump into a C++ exception; `END_RCPP` resumes it once the stack has unwound. Costs about 0.35 us per call.

**`sparseImage` stores its values already shaped** as `c(elements, stored)`, which is what makes `maskedMatrix()` zero-copy. R duplicates on `dim<-` when a vector is shared with an S7 object, so shaping at construction is the only way to avoid a copy.

**`voxelApply()` over a sparse image does not skip absent locations.** It gathers zeros for them and still calls the function. Sparsity buys memory, not time. Use `mask =` to skip, which works in the packed space and scatters back.

## S7 is used, and it has sharp edges

All of these were found the hard way:

- **Class names are package-qualified.** `class(x)[1]` is `"imply::denseImage"`, so `inherits(x, "denseImage")` is `FALSE` and **no S3 method dispatches**. Use `isDenseImage()` / `isSparseImage()` / `isPackedImage()`, and register methods with `S7::method()`.
- **`S7::methods_register()` must be called in `.onLoad`**, or methods are recorded but never activated — silently. `print` just falls through to the array method.
- **The `Ops` group generic cannot be dispatched on** usefully. The 15 binary operators are registered individually across several signatures, generated programmatically via `` S7::`method<-` `` in `registerSparseMethods()` and `registerPackedMethods()`.
- **Unary minus is unreachable.** R resolves `-x` through S3 group dispatch, which finds S7's own `Ops.S7_object` first. Use `0 - x` or `x * -1`. Likewise `!` cannot be registered, because S7 does not count it as an `Ops` member. Both are fixed by RConsortium/S7#490, which is approved but conflicted.
- **`dim` is a reserved property name**, hence the `dims` property with a `dim()` method. Allowed again in S7's development version.
- **Unions cannot be parents**, which is why `denseImage` has the `array` S3 class as its parent rather than `class_double` — otherwise every image would be forced to one storage mode.
- S7's multiple dispatch is built on S4, so `S4_register()` pulls in `methods`.

## A build trap worth remembering

`Rcpp::compileAttributes()` auto-includes `inst/include/imply.h` **before** `<Rcpp.h>` in `RcppExports.cpp`. Since the umbrella header pulls in `Parallel.h`, and libdispatch's system headers `#define FALSE 0`, this shadows R's `Rboolean` enumerators and breaks `R_useDynamicSymbols(dll, FALSE)`. Hence the `#undef FALSE` / `#undef TRUE` in `Parallel.h`, which is what R's own `Boolean.h` does for the same reason.

## Testing

`tinytest`, one file per area under `inst/tinytest/`, currently over 2,000 assertions. The dominant pattern is **differential testing against a reference**: `base::apply` for `imapply`, the dense image for every sparse or narrow operation. Prefer this to fixed expected values.

Where a claim is about memory or speed, assert the *ratio* rather than an absolute figure, so the test is not brittle across machines.

Do not put real `SIGINT` raising in the suite — it kills the test process. Interruption is verified manually; the suite checks that adding the interrupt and unwind machinery changed no answer.

## Known gaps and deferred work

- `FixedRaster<D>` and `dispatchDims` are not used by any shipping code path. Either wire them into the apply and reduce engines or remove them.
- No lazy or memory-mapped input, and no file-backed sink. The `Sink` interface exists so the latter can be added without touching kernels.
- Interleaved (voxel-major) storage for dense images is designed for — the container carries general strides — but not implemented. Benchmark before adding: blocked traversal already recovers most of the benefit for whole-image sweeps.
- `imreduce()` has no `progress` argument, since its loop runs on worker threads.
- `DESCRIPTION` has no `Depends: R (>= …)`. S7 needs R >= 3.5.0, but `CXX_STD = CXX17` really needs GCC 7+ / clang 5+, which an R 3.5-era toolchain will not have.
